# Code Generation Plan — u4-user-accounts

## Summary

- Builds: Akun dan sesi nyata (login/logout, sesi token-hash, tiga role admin/editor/viewer, penguncian 5 gagal/15 menit, ganti kata sandi, kelola akun oleh admin, catatan audit, admin pertama dari lingkungan, pembuat DDCL, pembersihan terjadwal, skrip pemulihan) menggantikan stub dev-mode di semua rute `/api/v1/*`, plus layar Login, Akun, Audit, dan Ganti Kata Sandi di frontend.
- Touches: `backend/prisma/` (skema + satu migrasi), `backend/src/` (modul akun, sesi, pintu hash, penegakan sesi/role/Origin, rute auth/users/audit, bootstrap, retensi, skrip pemulihan), `backend/tests/` (suite U1–U2 disesuaikan agar login), `frontend/src/` (AuthContext, 4 layar baru, klien API), `docker-compose.yml`, `.env.example`, `.github/workflows/ci.yml`, `README.md`, `contract-summary.md`.
- Tests: sekitar 120 test (unit, integrasi PostgreSQL nyata, API lewat `app.inject`, konkurensi, komponen React) ditambah 1 suite beban terpisah; seluruh suite U1–U2 dijalankan ulang sebagai regresi dan disesuaikan (login), bukan dilonggarkan.
- Adds: 2 elemen data-model yang tidak diminta langsung oleh artefak hulu (indeks `Session.userId`; nilai enum `AuditEvent.type` `account_reactivated`); see Assumptions

## Sumber dan keputusan yang dipakai

Semua dari artefak Unit ini: `functional-design/{functional-spec,rules,entities}.md` (BR4.1–BR4.20, W1–W11, matriks hak), `nfr-requirements/*` (NFR1.20–NFR1.25, NFR2.20–NFR2.33, NFR3.20–NFR3.27, NFR4.20–NFR4.21), `nfr-design/*` (rantai penegakan satu pintu, protokol A–hash–B, HashGate 2 slot, kunci penasihat start, retensi berkelompok), `infrastructure-design/*` (variabel lingkungan, urutan start, rotasi log, skrip pemulihan di image backend), `contract-design/contract-summary.md` (Contract 1–5), dan story US6.2 / AC6.2.1.

Urutan mengikuti Testing Contract: **test-after, per lapisan** (implementasikan lapisan, lalu tulis dan jalankan test lapisan itu sebelum lanjut). Tanpa dependensi baru: hash memakai `node:crypto` (`scrypt`, `randomBytes`, `createHash`, `timingSafeEqual`), cookie memakai `@fastify/cookie` dan CORS memakai `@fastify/cors` yang sudah ada.

Peta rute-ke-role mengikuti **NFR2.27** (menggantikan tabel di `functional-spec.md`, sesuai catatan NFR Requirements): rute U3 yang belum ada di kode (lock, submit, versions, capture-notes, `DELETE /ddcls/{id}`) tidak dibuat di Unit ini; U3 mendeklarasikan role minimalnya sendiri, dan rute tanpa deklarasi bernilai admin.

### Fase C — Logika bisnis (BR4.1, BR4.2, BR4.5, BR4.6, BR4.9, BR4.15, BR4.17, BR4.19; NFR1.24, NFR2.20, NFR2.28)

## Assumptions

- Indeks `Session.userId` ditambahkan di Step 3. Tidak ada artefak yang menyebutnya langsung; tanpa indeks, pencabutan semua sesi satu akun (BR4.12, BR4.13, BR4.18, dan pemulihan) memindai seluruh tabel `Session`.
- Nilai enum `AuditEvent.type` `account_reactivated` ditambahkan di Step 3. `entities.md` hanya mendaftar sepuluh jenis, sedangkan NFR3.22 meminta skrip pemulihan menulis `account_reactivated` (mengaktifkan kembali akun); tanpa nilai ini aksi itu tidak punya jenis audit yang sah.
- `DdclDocument.createdBy` (kolom string stub) dihapus dalam migrasi yang sama dan `createdBy` pada respons DDCL kini **diturunkan** (nama pembuat lewat join), bukan kolom. `entities.md` menyatakan `createdBy` "diganti" `createdByUserId`; mempertahankan field respons `createdBy` mencegah perubahan bentuk kontrak untuk `ComposeScreen`. `createdByUserId` juga ikut di respons untuk dipakai U5.
- Bentuk respons `GET /audit-events` (`{ items, nextCursor }` dengan `nextCursor` berisi `occurredAt` dan `id`) dan `GET /users` (larik akun) dipilih di sini karena Contract 1 belum menetapkannya; `contract-summary.md` diperbarui di Step 24 untuk mencatatnya.
- Validasi input memakai fungsi validasi domain (pola U1/U2), bukan skema JSON Fastify, karena koersi tipe Ajv bisa mengubah nilai non-teks menjadi teks sebelum validasi; batas dan kode status yang dijanjikan NFR2.28 tidak berubah.
- Migrasi ditulis tangan (setara `--create-only`) dan dibandingkan dengan `prisma migrate diff` terhadap skema saat build dijalankan; tidak ada `NOT NULL` pada `createdByUserId` (reliability-design).

## Risiko yang dibawa

- Seluruh suite U1–U2 harus diubah agar login; selisih perilaku (cookie stub hilang, `createdBy`) dicatat di `code-summary.md` sebagai penyesuaian, bukan pelonggaran asersi.
- Pembuatan admin, `pg_advisory_xact_lock`, dan skrip pemulihan dengan terminal interaktif nyata baru bisa dicoba penuh dengan Docker Compose utuh; test memakai fungsi inti dan `--password-stdin`.
- Test beban penuh (500.000 baris audit) hanya untuk jalan manual atau terjadwal.
